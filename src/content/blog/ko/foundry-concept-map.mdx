## 헷갈린 포인트

처음 정리할 때 가장 많이 헷갈린 부분입니다. 개념 이름을 누르면 위 카드로 이동합니다.

### 보기 · 제출 · 반영은 설정 위치가 다름

| 질문 | 설정 위치 | DB 비유 |
| --- | --- | --- |
| 누가 어떤 오브젝트를 보나? | [11 Object security policy](#concept-osp) | SELECT마다 DB가 자동 WHERE |
| 이 Action 제출해도 되나? | [6 Submission criteria](#concept-action) | UPDATE 전 IF 검사 |
| 실제 저장은 언제? | [7 Action 실행 때만](#concept-function) | COMMIT. edit function은 변경 SQL 만들기까지만 |

### 토큰 권한 = 세 범위의 교집합

| 범위 | 주문 | 고객 | 재고 |
| --- | :-: | :-: | :-: |
| 사용자 권한 | ✓ | ✓ | ✓ |
| 앱 최대 scope | ✓ | ✗ | ✓ |
| 요청 scope | ✓ | ✓ | ✗ |
| **토큰 접근** | **✓** | ✗ | ✗ |

요청 scope는 브라우저 코드가 정함 → 믿을 경계는 Developer Console에 저장된 최대 scope뿐. ([9 OSDK 카드](#concept-osdk))

### 권한이 따로 노는 곳

- [11 Object security policy](#concept-osp) ↔ 데이터셋 권한: 양방향 분리. 원본 데이터셋은 따로 잠가야 함.
- [8 Media set](#concept-media) 권한 ↔ 오브젝트 정책: 별개. property 못 봐도 media set에서 파일 직접 가져올 수 있음.
- [9 OSDK](#concept-osdk) scope: 앱 전체 상한일 뿐. 사용자별 차등, "앱으로만 접근" 강제 불가.
- [12 Compute module](#concept-cm) Application permissions: 호출자 무관, 서비스 유저 권한 고정.

## 심화 때 확인할 것

공식 문서로 아직 확인하지 못한 항목입니다.

- [2 Dataset](#concept-dataset): 보존 정책으로 옛 트랜잭션 파일이 정리되면 롤백 가능한지 — 확인 필요
- [8 Media set](#concept-media): 덮어쓴 옛 media item의 보존·삭제 정책 — 확인 필요
- [10 OAuth](#concept-oauth): OSDK 인증 라이브러리가 PKCE를 자동 처리하는지 — 확인 필요
- [+1 Pipeline Builder](#concept-pb): 생성 코드를 Code Repositories로 꺼내 편집할 수 있는지 — 확인 필요
- [+2 Ontology Manager](#concept-oma): SuperRepo(베타)가 사용 중인 환경에서 제공되는지 — 환경별 확인
- [+3 Global Branching](#concept-branch): OSDK React 앱·Developer Console이 Global Branching과 연동되는지 — 확인 필요
